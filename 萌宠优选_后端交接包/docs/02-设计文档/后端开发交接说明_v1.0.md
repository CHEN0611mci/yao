## 6 数据库交接（重点）

### 6.1 连接信息

| 项 | 值 |
|---|---|
| 库名 | **`shop`**（不是 `pet_mall`；`pet_mall` 只是参考库，可删） |
| 连接串 | `jdbc:mysql://localhost:3306/shop?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8` |
| 账号 | 由 `config/backend.env` 的 `DB_USERNAME` / `DB_PASSWORD` 注入，不写死在源码 |
| 配置位置 | `backend/ruoyi-admin/src/main/resources/application-druid.yml`（全部 `${ENV:默认值}`） |
| 建议 | 本地无证书，`useSSL=true` 若出现握手告警，改成 `useSSL=false` |

### 6.2 业务表（14 张，已建好）

`pet_member`（会员）、`pet_member_pet`（宠物档案）、`pet_address`、`pet_category`、`pet_item`（SPU）、`pet_item_sku`、`pet_item_image`、`pet_item_audit`、`pet_cart_item`、`pet_order`、`pet_order_item`、`pet_payment`、`pet_stock_log`、`pet_message`。

已内置的关键约束：

- 防超卖：`pet_item_sku.stock INT` + `CHECK (stock >= 0)`；
- 下单幂等：`pet_order.uk_client_token`；
- 支付幂等：`pet_payment.uk_idempotency_key`；
- 防重复扣减/回滚：`pet_stock_log.uk_sku_order_type(sku_id, order_no, type)`；
- 订单状态：**0–8 九状态**（0 待付款、1 待审核、2 待发货、3 待收货、4 已完成、5 已取消、6 已关闭、7 售后中、8 已退款）；
- 收货/宠物/商品均存**快照**；
- **不建物理外键**，引用完整性由 Service 层保证。

### 6.3 关键业务约定（开发时必须遵守）

| 约定 | 说明 |
|---|---|
| 商家绑定 | `sys_user.dept_id = merchant_id = 9001`（`merchant1` 账号）；商品/订单按 `merchant_id` 隔离 |
| 会员/后台双域 | 后台 Token 走若依 `login_tokens:`；会员 Token 用独立前缀（建议 `member_tokens:`），互不通用 |
| 商品可售 | `status=1 AND audit_status=2 AND del_flag='0'`；库存看 SKU |
| 扣减 SQL | `UPDATE pet_item_sku SET stock=stock-#{qty} WHERE id=#{skuId} AND stock>=#{qty}`，影响 0 行 → `PET-3001` 并整单回滚 |
| 库存流水 | 每个 SKU 种子内置一条 `ADJUST` 初始库存；下单写 `DEDUCT`，取消/关单写 `ROLLBACK`；满足 `Σchange_qty = stock` |
| 支付回调 | `Idempotency-Key` 必须落 `pet_payment.idempotency_key`；重复命中唯一键直接返回成功且不改订单 |
| 超时关单 | Quartz 每分钟扫描 `status=0 AND create_time < NOW()-mall.pay-timeout-minutes`，条件更新 `WHERE status=0`，再回滚库存；演示可把参数调成 1 |
| 备注 | 商品/订单等主数据逻辑删除用 `del_flag`；交易数据只增不删 |
| 金额 | 全部 `BigDecimal` + `DECIMAL(10,2)`，禁止 double/float |

### 6.4 绝对不能做的操作

- ❌ 不要对当前 `shop` 执行 `db/01_base.sql`（会重建若依 31 张表，清空现有数据）；
- ❌ 不要 `DROP`/`TRUNCATE` 业务表，生产/演示库变更走 `ALTER` 迁移；
- ❌ 不要在他人正在演示时执行 `03_seed.sql`（会重置业务数据与订单时间）。

## 7 工程结构与代码约定

### 7.1 源码位置

后端：`backend/`（RuoYi 3.9.2 多模块 Maven 工程，已包含 `ruoyi-mall`）。`dist/ruoyi-admin.jar` 为已构建产物。

### 7.2 新增模块 `ruoyi-mall`

```text
shop/RuoYi-Vue-master/
├─ pom.xml                          # 增加 <module>ruoyi-mall</module>
├─ ruoyi-mall/                      # 新增业务模块
│  ├─ pom.xml
│  └─ src/main/java/com/ruoyi/mall/
│     ├─ domain/                    # 实体（对应 14 张表）
│     ├─ mapper/                    # Mapper 接口（@MapperScan 已覆盖 com.ruoyi.**.mapper）
│     ├─ service/ + service/impl/
│     ├─ common/                    # Result/PageResult/BizException/ErrorCode/枚举
│     ├─ state/                     # 订单状态机
│     └─ job/                       # 关单、自动收货任务
└─ ruoyi-admin/                  # 启动类、系统 Controller、application*.yml
```

> 实际实现中商城 Controller 位于 `ruoyi-mall/src/main/java/com/ruoyi/mall/controller/`，Mapper XML 位于 `ruoyi-mall/src/main/resources/mapper/mall/`。

- `ruoyi-admin/pom.xml` 增加 `ruoyi-mall` 依赖；
- Mapper XML 放 `ruoyi-mall/src/main/resources/mapper/mall/*Mapper.xml`（`mapperLocations: classpath*:mapper/**/*Mapper.xml` 已覆盖）；
- `@MapperScan("com.ruoyi.**.mapper")` 已覆盖新包；
- `typeAliasesPackage: com.ruoyi.**.domain` 已覆盖；
- 若新增模块导致构建问题，退化为在 `ruoyi-admin` 下建 `com.ruoyi.mall` 包（设计文档允许，结论不变）。

### 7.4 其他配置项

- `token.secret` 已外置为 `TOKEN_SECRET`，正式环境必须更换；

### 7.5 分层与事务

- Controller → Service → Mapper，禁止 Controller 写 SQL、Service 依赖 HttpServletRequest；
- 事务边界只在 Service 公有方法加 `@Transactional(rollbackFor = Exception.class)`；
- 先按 `sku_id` 升序扣减，降低死锁概率；状态更新一律条件更新（`WHERE order_no=? AND status=?`）；
- 统一返回 `Result<T>`、分页 `PageResult<T>`、异常 `BizException` + 错误码 `PET-xxxx`（SRS §8.4 / 设计 §7.3）。

## 8 鉴权与权限约定

| 端 | 机制 | 说明 |
|---|---|---|
| 后台 | 若依 JWT + `@PreAuthorize("@ss.hasPermi('mall:xxx')")` | 权限码已 seed 到 `sys_menu`，角色：商家 `merchant`、审核员 `reviewer` |
| 前台 | 新增 `@MemberLogin` 注解 + 拦截器 | 从 `Authorization` 取会员 Token，校验 Redis `member_tokens:*`，把 `memberId` 写入 request attribute/ThreadLocal |
| 双域隔离 | Redis key 前缀分离 | 后台 `login_tokens:`、会员 `member_tokens:`，互不通用 |
| 归属校验 | Service 层 `OwnershipChecker` | 会员只能操作本人地址/订单/档案；商家只能操作 `merchant_id=9001` 的商品/订单 |
| 审计 | 后台写操作加 `@Log(title=..., businessType=...)` | 落 `sys_oper_log` |
| 按钮级 | 前端 `v-hasPermi` + 后端二次校验 | 不能只靠前端隐藏 |

**权限码清单**（设计 §9.3.2，已 seed）：
`mall:item:list/add/edit/audit/status`、`mall:category:list/add/edit/remove`、`mall:order:list/ship`、`mall:member:list/status`、`mall:stock:list`、`mall:audit:list`、`mall:dashboard:view`、`mall:job:trigger`、`mall:merchant:item:*`、`mall:merchant:order:*`。

## 9 建议任务拆分与顺序（按依赖排序）

### 迭代 1：工程骨架 + 会员域（约 1.5 天）

| 任务 | 产出/验收 |
|---|---|
| 新建 `ruoyi-mall` 模块并接入 `ruoyi-admin` | `mvn -pl ruoyi-admin -am package` 成功，应用能启动 |
| `Result/PageResult/BizException/ErrorCode` | 统一返回与异常处理；HTTP 状态码 + 业务码 |
| 会员注册/登录/登出/`me` + `@MemberLogin` 拦截器 | 未登录 401；登录返回 Token；BCrypt 校验 |
| 宠物档案 CRUD、地址 CRUD/设默认 | 本人数据隔离；最多 5 只宠物、20 个地址（`mall.pet-max`/`mall.address-max`） |
| 首个 Swagger 分组 | `/swagger-ui.html` 能看到会员接口 |

### 迭代 2：商品域 + 审核（约 2 天）

- 分类树/首页分类/推荐；商品列表（keyword/category/species/ageStage/price/sort/分页）；商品详情 + SKU + 适用性提示；
- 商家商品发布/编辑/上下架（归属校验）；管理员商品列表/审核通过/驳回（`pet_item_audit` 留痕）；
- 商品可售条件：`status=1 AND audit_status=2 AND del_flag='0'`。

### 迭代 3：购物车 + 下单 + 库存（约 2 天，核心）

- 购物车：加购（校验上架/库存）、改数量、删除、勾选、合计；`uk_member_sku` 去重累加；
- 结算试算：服务端重算金额 + 运费（`mall.freight-*`）；
- 提交订单事务：校验 → 原子扣库存（影响 0 行抛 `PET-3001`）→ 写订单/明细快照 → 清购物车 → 写 `DEDUCT` 流水；同事务；
- 订单六页签/详情/取消（回滚库存 + `ROLLBACK` 流水）；`StockConcurrentTest` 20 线程抢库存 1。

### 迭代 4：支付 + 履约（约 2 天，差异化重点）

- 模拟支付三分支（SUCCESS/FAIL/TIMEOUT）+ 支付记录；
- 回调幂等：`Idempotency-Key` 唯一键，重放直接成功；金额校验；状态机推进；
- 超时关单：Quartz 每分钟扫描，条件更新 `status=0→6`，逐单回滚库存 + `ROLLBACK` 流水；提供手动触发接口 `mall:job:trigger`；
- 发货（商家/管理员）、确认收货、自动确认收货；状态机矩阵单测覆盖全部合法/非法迁移。

### 迭代 5：安全与质量（约 1.5 天）

- 越权拦截（会员/商家/后台三类 403 + 审计）；审计日志页；限流（登录/下单）；手机号/地址脱敏；
- Redis 缓存分类/推荐（TTL），做缓存前后压测对比；
- 单测覆盖率（核心 Service ≥60%）、幂等/超时测试、Swagger 注解、Actuator 健康检查。

> 里程碑参考（规划稿 §8）：D7 前跑通"登录 → 看商品 → 加购"；D12 前跑通"下单 → 支付 → 发货 → 收货"。

## 11 常见坑清单（先看再动手）

1. **JDK 25 是默认值**：直接用 `java`/IDEA 默认会跑 25，必须切 17；
2. **Maven 未安装**：CLI 构建前先装 3.9.x；IDEA 可用内置 Maven 先跑；
3. **Redis 未启动**：不启动则登录/Token 全部失败，先 `redis-server.exe`；
4. **`useSSL=true`**：本地无证书可能有握手告警，必要时改 `false`；
5. **文件上传路径** `D:/ruoyi/uploadPath` 不存在：商品图片上传会失败，改成项目内目录；
6. **Springdoc 只扫 tool 包**：商城接口不会出现在 Swagger，按 §7.3 修改；
7. **`01_base.sql` 会重建若依表**：当前 `shop` 已有数据，严禁执行；
8. **`03_seed.sql` 会重置业务数据**：演示前才跑，跑完订单时间为当前时间，正好演示超时关单；
9. **`pet_member_pet.species` 是 `VARCHAR(10)`**（设计文档原 `CHAR(2)`，已修正，以数据库为准）；
10. **`merchant_id` 通过 `sys_user.dept_id` 绑定**，不是 `sys_user.user_id`；
11. **没有物理外键**：删除/校验引用要靠 Service；
12. **`sys_config` 没有 `config_key` 唯一索引**：初始化脚本用 DELETE+INSERT，业务代码读取即可；
13. **中文乱码**：执行 SQL 必须带 `--default-character-set=utf8mb4`；源码/日志统一 UTF-8；
14. **前端代理**：管理前端 `/dev-api` → `http://localhost:8080`，会员端新建 `user-ui` 时同样代理 `/api`；
15. **`npm.ps1` 被拦截**：一律 `npm.cmd run dev`；
16. **`pet_mall` 参考库**：不要连错库；确认不用后 `DROP DATABASE pet_mall;`。
