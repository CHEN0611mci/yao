# 用户端（`user-ui`）项目设计 v1.0

> 项目：萌宠优选 · 宠物商城系统
> 文档编号：PET-MALL-FE-USER-001　｜　版本：v1.0　｜　日期：2026-10-19
> 设计依据：《宠物商城系统_企业级需求文档_v2.0》C-01～C-14、附录 A；《宠物商城系统_企业级设计文档_v1.0》§5 前端设计、§6 数据库、§7 接口设计、§8 关键场景、§9 安全
> 定位：本文是 `user-ui`（客户前台）的落地设计，重点覆盖**客户用户体系 + 前端工程骨架 + 页面/组件/状态/Mock/验收**。后台 `admin-ui` 不在本文范围。

---

## 1 目标、范围与边界

### 1.1 一句话目标

为游客与会员提供一个**独立于管理后台**的商城 SPA（端口 81），完成"浏览 → 登录/注册 → 建宠物档案 → 加购 → 下单 → 支付 → 订单跟踪 → 确认收货"的客户主闭环，并支持在**后端接口未就绪时用 Mock 独立开发和演示**。

### 1.2 一期范围（10 个页面族）

| 域 | 页面 |
|---|---|
| 浏览 | 首页、商品列表、搜索结果（复用列表）、商品详情 |
| 账号 | 登录、注册 |
| 交易 | 购物车、结算页、支付页、支付结果、订单列表（六页签）、订单详情 |
| 会员 | 个人中心、宠物档案、地址管理、消息中心、用户协议/隐私政策 |
| 通用 | 404 |

> 售后、订阅、评价、优惠券、积分、收藏等为二期，一期只保留**入口占位与提示**，不实现业务。

### 1.3 与 `admin-ui` 的边界（必须隔离）

| 维度 | `user-ui`（客户） | `admin-ui`（管理后台） |
|---|---|---|
| 使用者 | 游客、会员 | 管理员、商家、审核员 |
| 端口 | 81 | 80 |
| 账号体系 | `pet_member` + `member_tokens:*` | `sys_user` + 若依 JWT/Redis |
| 接口前缀 | `/api/**` | `/api/admin/**`、`/api/merchant/**`、若依 `/system/**` |
| 鉴权方式 | `@MemberLogin`（后端拦截器） | Spring Security + `@PreAuthorize` |
| 前端权限 | 无菜单 RBAC，只有登录态与本人数据 | 菜单 + 按钮权限码 `mall:*` |
| 构建产物 | 独立 `dist/` | 独立 `dist/` |

**原则**：两端不共享登录态、不共享 axios 实例、不共享路由；会员 Token 访问 `/api/admin/**` 必须 403，后台 Token 也不能访问会员接口。

### 1.4 本期不做什么

- 不做小程序/H5 独立端（同一套 Vue 页面做响应式适配）；
- 不做真实支付（使用后端沙箱支付三分支）；
- 不做售后/订阅/评价/优惠券/积分/收藏/客服会话；
- 不做服务端渲染与 SEO（一期 SPA 够用，商品详情 URL 可后续改造）；
- 不引入 UI 框架之外的大型组件库（避免包体与风格失控）。

## 2 客户用户体系设计

> 后端表结构已落地（`pet_member`/`pet_member_pet`/`pet_address` 等），本节定义**前端如何使用这套用户体系**，不重复 DB 设计。

### 2.1 角色与会员状态

| 角色 | 能力 |
|---|---|
| 游客 | 浏览首页/分类/搜索/详情；本地购物车；访问需登录页面时被拦截并引导登录 |
| 会员 | 全部浏览能力 + 档案/地址/购物车/下单/支付/订单/消息/账号安全 |

会员状态：`status=0 正常` / `status=1 禁用`；`del_flag='1'` 为逻辑删除。被禁用会员的 Token 由后端失效，前端收到 401 后清理登录态。

### 2.2 注册与登录

| 项 | 设计 |
|---|---|
| 注册字段 | 用户名（4–20 位，唯一）、手机号（11 位，唯一，脱敏展示）、密码（6–20 位，字母+数字）、确认密码、昵称（默认"萌宠用户"+随机）、勾选《用户协议》《隐私政策》 |
| 注册接口 | `POST /api/member/register`；成功后返回 Token + 会员信息，直接进入登录态 |
| 登录方式 | 一期账号密码；可选图形验证码；手机验证码/微信登录为二期 |
| 登录接口 | `POST /api/member/login`，返回 `token`、`expiresIn`（7 天）、`member`（手机号脱敏） |
| 登录失败 | 连续 5 次失败锁定 10 分钟（后端控制）；前端展示 `PET-2002` 文案 |
| Token 存储 | `localStorage.member_token`；请求头 `Authorization: Bearer <token>` |
| 登出 | `POST /api/member/logout` + 清理 Pinia/localStorage；跳首页 |
| 未登录拦截 | 路由 `meta.requiresAuth`；跳 `/login?redirect=<当前路径>`，登录后回跳 |
| Token 过期 | 任意接口返回 401/`PET-2001` → 清登录态 → 登录页提示"登录已过期，请重新登录" |
| 账号安全 | 修改密码（原密码 + 新密码，成功后强制重新登录）；退出登录；登录设备/注销为二期 |

### 2.3 会员资料、档案与地址

| 模块 | 规则（前端需体现） |
|---|---|
| 个人资料 | 头像、昵称、性别、生日、手机号（脱敏只读，换绑为二期）；`PUT /api/member/me` |
| 宠物档案 | 最多 5 只（`mall.pet-max`）；字段：名字、物种 CAT/DOG/SMALL、品种、生日、体重、是否绝育、过敏源；用于列表/详情的适用性提示与"为谁购买" |
| 收货地址 | 最多 20 个（`mall.address-max`）；省/市/区级联、详细地址、默认地址唯一；订单只存快照 |
| 数据归属 | 所有会员接口的 `memberId` 由后端从 Token 解析，前端**不传** `memberId`；前端不缓存他人数据 |
| 消息中心 | 未读数角标；分类（订单/系统）；标记已读、全部已读、跳转对应订单 |

### 2.4 客户主流程（一期）

```text
游客浏览/搜索/详情
  → 登录/注册（未登录加购/下单时回跳）
  → 建/选宠物档案、选地址
  → 加购（库存/上架/适配校验）
  → 购物车勾选 → 结算试算
  → 提交订单（clientToken 防重复）
  → 支付沙箱（成功/失败/超时）
  → 商家发货 → 确认收货 → 订单完成
异常线：取消订单 / 超时未支付自动关闭 / 支付失败重试
```

### 2.5 用户体系接口契约（前端消费）

| 方法 | 路径 | 鉴权 | 前端使用页面 |
|---|---|---|---|
| POST | `/api/member/register` | 匿名 | 注册 |
| POST | `/api/member/login` | 匿名 | 登录 |
| POST | `/api/member/logout` | 会员 | 个人中心/退出 |
| GET/PUT | `/api/member/me` | 会员 | 个人中心 |
| GET/POST | `/api/member/pets` | 会员 | 宠物档案列表/新增 |
| PUT/DELETE | `/api/member/pets/{id}` | 会员 | 编辑/归档 |
| GET/POST | `/api/member/addresses` | 会员 | 地址管理/结算新增 |
| PUT/DELETE | `/api/member/addresses/{id}` | 会员 | 编辑/删除 |
| PUT | `/api/member/addresses/{id}/default` | 会员 | 设默认 |
| GET | `/api/member/messages` | 会员 | 消息中心/顶部角标 |
| PUT | `/api/member/messages/{id}/read` | 会员 | 标记已读 |

关键响应示例（登录）：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "expiresIn": 604800,
    "member": { "id": 1001, "nickname": "奶糖爸爸", "phone": "138****8001", "avatar": "..." }
  },
  "traceId": "..."
}
```

### 2.6 与后台会员管理的关系

- 后台"会员管理"操作的是同一张 `pet_member` 表（列表、禁用/启用）；
- 禁用后后端使该会员 Token 失效，前端下一次请求 401 → 回登录页；
- 后台看不到会员密码；会员也永远无法进入 `/api/admin/**`。

## 3 前端工程方案

### 3.1 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Vue 3（Composition API + `<script setup>`） | 与教材/管理端一致 |
| 构建 | Vite 6 | 端口 81，代理 `/api` → `http://localhost:8080` |
| UI | Element Plus + 自定义主题 | 成熟表单/弹窗/表格；主题色改为品牌色 |
| 状态 | Pinia | member/cart/pet/app 四个 store |
| 路由 | Vue Router 4 | History 模式；`meta.requiresAuth` |
| 请求 | Axios | 单实例 + 拦截器；统一 `Result`/`PageResult` |
| 工具 | dayjs、lodash-es（按需） | 日期、防抖/深拷贝 |
| Mock | `vite-plugin-mock` 或 MSW（二选一） | 与后端并行开发的关键 |
| 测试 | Vitest + Playwright（可选） | 组件测试与主干 E2E |

**工程形态决策**：独立 `user-ui`，不与管理端合并。理由：双域 Token、路由守卫、菜单体系、构建与演示都更清晰；管理端可零成本复用若依，客户前台专注消费体验。

| 路由 | 页面 | 鉴权 | 布局 | 主要接口 |

| `/` | 首页 | 匿名 | Default | `/api/home/categories`、`/api/home/recommend` |

| `/items/:id` | 商品详情 | 匿名 | Default | `/api/items/{id}` |

| `/orders` | 订单列表（六页签） | 会员 | Default | `/api/orders?status=` |
| `/orders/:orderNo` | 订单详情 | 会员 | Default | `/api/orders/{orderNo}` |
| `/member` | 个人中心 | 会员 | Default | `/api/member/me`、消息未读数 |

| `/member/addresses` | 地址管理 | 会员 | Default | `/api/member/addresses` |
| `/messages` | 消息中心 | 会员 | Default | `/api/member/messages` |
| `/agreement` | 协议/隐私 | 匿名 | Blank | 静态内容 |
| `/:pathMatch(.*)*` | 404 | 匿名 | Blank | — |

### 4.2 路由守卫规则

| 场景 | 行为 |
|---|---|
| 匿名访问公开页 | 放行；已登录访问 `/login`、`/register` 重定向首页 |
| 匿名访问会员页 | 跳 `/login?redirect=<encodeURIComponent(fullPath)>` |
| 登录成功 | 若存在 `redirect` 且为站内路径则回跳，否则首页 |
| Token 过期/401 | 清理 member store 与 localStorage → 登录页提示"登录已过期" |
| 404 | 渲染 404 页，提供"返回首页/去逛逛" |
| 查询参数 | 列表筛选/排序/分页、订单页签全部放 URL query，刷新/回退不丢状态 |

## 5 页面级设计

### 5.1 首页 `/`

| 项 | 设计 |
|---|---|
| 目标 | 3 秒内让用户知道"这里能买宠物用品，并能按我家宠物筛选" |
| 模块 | 顶部导航（Logo/搜索/消息/购物车角标/登录态）；Banner；快捷分类（猫/犬/小宠/用品）；宠物档案快捷卡；推荐商品楼层；服务承诺；页脚 |
| 数据 | `GET /api/home/categories`（Redis 30 min）、`GET /api/home/recommend`（10 min） |
| 状态 | 骨架屏；分类为空隐藏楼层；图片失败占位；接口失败重试 |
| 交互 | 点击分类带 `categoryId` 跳列表；点击档案卡跳档案页；未登录点"为宠物推荐"引导登录/建档 |
| 验收 | 匿名可见；推荐位有数据；购物车角标随 store 变化；移动端底部导航可用 |

### 5.2 商品列表/搜索 `/items`、`/search`

| 项 | 设计 |
|---|---|
| 目标 | 快速找到符合"宠物种类/年龄/价格/关键词"的商品 |
| 模块 | 分类侧栏/顶部标签；筛选栏（物种、年龄段、价格区间、仅看有货）；排序（综合/销量/价格升降/上新）；商品瀑布流/网格；分页或加载更多；搜索历史 |
| 数据 | `GET /api/items?keyword=&categoryId=&species=&ageStage=&priceMin=&priceMax=&sort=&pageNum=&pageSize=` |
| 状态 | 骨架屏；空结果 + 推荐热销 + 清空筛选；筛选条件回显；返回保留状态 |
| 交互 | 筛选/排序/分页写入 query；移动端滚动加载；`ItemCard` 整卡可点 |
| 验收 | 8 个筛选/排序组合可用；空态正确；URL 可分享/刷新保持 |

### 5.3 商品详情 `/items/:id`

| 项 | 设计 |
|---|---|
| 目标 | 让用户确认"适合我家宠物"并完成加购 |
| 模块 | 主图/图集；标题、卖点、价格、划线价、销量；适用物种/年龄/体重标签；**适用性提示卡**（适合/需注意/不适合 + 原因）；SKU 规格选择（售罄置灰、价格库存联动）；数量步进；加购/立即购买；服务承诺；详情富文本；推荐商品 |
| 数据 | `GET /api/items/{id}`（登录后返回适配结论；匿名只返回商品属性） |
| 状态 | 加载骨架；SKU 缺货禁用；库存 0 按钮禁用；详情图失败占位 |
| 交互 | 未登录加购 → 登录弹窗/跳登录并回跳；适配冲突二次确认；数量 ≤ 库存与 99；加购后角标 +1 |
| 验收 | 库存 1/0 的 SKU 展示正确；适配结论有原因；加购成功提示并可去购物车 |

### 5.4 登录/注册 `/login`、`/register`

| 项 | 设计 |
|---|---|
| 模块 | Logo/欢迎语；账号密码；可选验证码；登录按钮；去注册；协议勾选（注册）；开发环境提示测试账号 |

## 7 状态管理（Pinia）

| Store | 状态 | 主要 action | 持久化 |
|---|---|---|---|
| `member` | `token`、`profile`、`isLogin`、`unreadCount` | `login`、`logout`、`loadProfile`、`setUnread` | token + profile 存 localStorage |
| `cart` | `items`、`checkedIds`、`totalAmount`、`totalQty` | `load`、`add`、`updateQty`、`toggle`、`remove`、`mergeGuestCart`、`clear` | 游客购物车存 localStorage |
| `pet` | `pets`、`currentPetId` | `load`、`select`、`create`、`update`、`archive` | 无（每次登录加载） |
| `app` | `categories`、`searchHistory`、`isMobile` | `loadCategories`、`addHistory`、`clearHistory` | 搜索历史 localStorage |

**原则**：
- 登录态、购物车、宠物档案是跨页面共享 → Pinia；
- 筛选、排序、分页、订单页签 → URL query；
- 页面内弹窗/表单状态 → 组件本地 state，避免全局膨胀。

## 8 API 层与 Mock 方案

### 8.1 请求层约定

```javascript
// utils/request.js（要点）
const service = axios.create({ baseURL: import.meta.env.VITE_API_BASE, timeout: 15000 });

service.interceptors.request.use((config) => {
  const token = useMemberStore().token;
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

service.interceptors.response.use(
  (res) => {
    const body = res.data;
    if (body.code === 200) return body.data;
    if (body.code === 401 || body.code === 2001) {
      useMemberStore().logout();
      router.push({ path: '/login', query: { redirect: router.currentRoute.value.fullPath } });
    } else {
      ElMessage.error(`${body.message}（${(body.traceId || '').slice(-6)}）`);
    }
    return Promise.reject(body);
  },
  (err) => {
    if (err.response?.status === 429) ElMessage.warning('操作过于频繁，请稍后再试');
    else if (err.response?.status >= 500) ElMessage.error('系统繁忙，请稍后重试');
    return Promise.reject(err);
  }
);

export default service;
```

| 规则 | 说明 |
|---|---|
| 返回结构 | 后端统一 `Result{code,message,data,traceId}`，拦截器只暴露 `data` |
| 错误码 | `PET-1001` 参数、`PET-2001` 未登录、`PET-2003` 无权限、`PET-3001` 库存不足、`PET-3002` 状态不允许、`PET-4001` 重复提交… |
| 401 | 清理登录态，跳登录并回跳；不重复弹窗 |
| 429 | 按提示禁用按钮倒计时 |
| 重试 | GET 网络错误可重试 1 次；写接口禁止自动重试 |
| 金额 | 统一按字符串展示两位小数，禁止浮点运算 |

### 8.2 API 模块划分

`api/member.js`、`pet.js`、`address.js`、`item.js`、`cart.js`、`order.js`、`pay.js`、`message.js`；每个函数只做"参数 → 请求 → 返回 data"，不写业务判断。

### 8.3 Mock 策略（与后端并行的关键）

| 项 | 方案 |
|---|---|
| 开关 | `.env.development` 的 `VITE_USE_MOCK=true`；生产构建为 false |
| 实现 | 推荐 `vite-plugin-mock`（dev 拦截，零侵入）或 MSW（Service Worker，支持 preview） |
| 数据来源 | 从 `shop` 库种子数据导出：8 分类、12 商品、24 SKU、3 宠物、3 地址、2 订单、消息；保证页面像真实数据 |
| 目录 | `src/mock/data/*.json` + `src/mock/handlers/*.js`，一个后端域一个文件 |
| 契约 | 每个 Mock 响应必须与设计文档 §7 的 `Result`/`PageResult` 完全一致；字段变更同步改 Mock 文档 |
| 切换 | 后端接口就绪后，关掉对应 handler（不必改页面代码）；最终 `VITE_USE_MOCK=false` 全量联调 |

## 9 鉴权与前端安全

| 项 | 设计 |
|---|---|
| 路由鉴权 | `meta.requiresAuth` + 全局前置守卫；未登录跳登录并记录 `redirect` |
| Token | localStorage；只放 Token 与脱敏 profile；不存密码 |
| 越权 | 所有会员接口由后端从 Token 取 `memberId`；前端不传 `memberId`；不能访问 `/api/admin/**` |
| XSS | 商品详情富文本由后端白名单过滤；用户输入用纯文本插值，禁止 `v-html` 渲染评价/备注 |
| CSRF | Token 放 Header，不使用 Cookie 会话 |
| 敏感信息 | 手机号脱敏；不在 console 打印 Token/完整手机号；错误提示带 traceId 后 6 位 |
| 依赖 | 锁定 `package-lock.json`；不引 CDN 脚本；构建不开启 sourcemap 外泄 |

## 11 关键流程设计

### 11.1 登录回跳 + 游客购物车合并

```text
匿名加购 → 本地 localStorage 购物车
  → 点击结算/购物车 → 守卫跳 /login?redirect=/cart
  → 登录成功 → member store 写入 token/profile
  → 调用 mergeGuestCart() → POST /api/cart/items 逐条合并 → 清本地
  → 回跳 /cart
```

### 11.2 加购与库存/适配

```text
详情页选 SKU/数量 → 点击加购
  → 未登录：弹登录 → 回跳并保留选择
  → 已登录：POST /api/cart/items
      ├─ 成功：角标 +n，提示"已加入购物车"
      ├─ PET-3001：提示库存不足并刷新库存
      └─ 适配冲突：二次确认后允许加入
```

### 11.3 下单与重复提交

```text
进入结算 → 生成 clientToken（页面生命周期内唯一）
  → 选地址/确认金额 → 提交（按钮 loading + 请求锁）
  → POST /api/orders { addressId, clientToken, items[] }
      ├─ 成功：清空已选购物车 → 跳 /pay/:orderNo
      ├─ PET-3001：提示库存不足 → 回购物车
      └─ PET-4001：查询/返回原订单，避免重复下单
```

### 11.4 支付三分支

| 结果 | 前端行为 |
|---|---|
| SUCCESS | 跳结果页成功 → 查看订单/继续购物 |
| FAIL | 结果页失败 → 重新支付/取消订单 |
| TIMEOUT | 提示"支付超时，订单已关闭" → 刷新订单状态 |

> 支付结果最终以服务端回调/订单状态为准，前端轮询 3 次（2s）兜底。

### 11.5 订单六页签

`全部 / 待付款 / 待发货 / 待收货 / 已完成 / 已取消`；页签放 URL query `?status=`；操作后刷新当前页签并同步详情。

| Mock 与真实接口字段漂移 | 契约冻结 + Mock 文档 + 后端按同一份 JSON 实现 + 联调逐模块关闭 Mock |
| 页面数量多、时间不足 | 先保 10 页主闭环；售后/订阅/评价只放入口；必要时砍收藏/积分 |
| 两套前端维护成本 | `user-ui` 独立但复用组件规范；管理端只做业务页面，不复制客户 UI |
| 移动端适配返工 | 从 D1 开始用移动端优先布局与断点，不最后补 |
| Token 泄露 | localStorage + Header；不在 console 打印；XSS 过滤 |
| 图片资源缺失 | 统一占位图 + 失败重试；演示前用 seed 占位路径替换为真实图 |
| 支付结果误解 | 结果页以订单状态/回调为准，前端只做轮询兜底 |
