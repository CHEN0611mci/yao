## 4 表结构设计

### 4.1 设计原则落地（对应设计 §6.1 DB-01～DB-10）

| 编号 | 原则 | 落地方式 |
|---|---|---|
| DB-01 | 交易数据只增不改 | 订单、明细、支付、库存流水无删除接口；订单状态仅经状态机条件更新 |
| DB-02 | 主数据逻辑删除 | `pet_member.del_flag`、`pet_item.del_flag`；分类未加 `del_flag`（以 `status` 停用，遵循设计 DDL） |
| DB-03 | 快照优先 | `pet_order.receiver_snapshot`/`pet_snapshot`、`pet_order_item` 的标题/规格/价格/图片/宠物快照 |
| DB-04 | 唯一索引即业务约束 | `uk_username`/`uk_phone`/`uk_sku_code`/`uk_member_sku`/`uk_order_no`/`uk_client_token`/`uk_payment_no`/`uk_idempotency_key`/`uk_sku_order_type` 共 9 个 |
| DB-05 | 金额定点数 | 全部金额 `DECIMAL(10,2)`，无 float/double |
| DB-06 | 不建物理外键 | 14 张业务表均无 FOREIGN KEY，引用完整性由应用层保证 |
| DB-07 | 字符集统一 | 业务表显式 `DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci` |
| DB-08 | 时间统一 | `create_time` 默认 `CURRENT_TIMESTAMP`；连接串时区 Asia/Shanghai；服务端 `NOW()` 写入 |
| DB-09 | 命名统一 | `pet_` 前缀、`uk_` 唯一键、`idx_` 普通索引、`chk_` 约束 |
| DB-10 | 可对账 | 库存 `ADJUST` 流水承载初始库存；支付金额可与订单应付对账（校验脚本 C01/C04） |

### 4.2 业务表清单与约束

| # | 表 | 主键 | 唯一键 | 普通索引 | CHECK 约束 |
|---|---|---|---|---|---|
| 1 | `pet_member` | `id` | `uk_username`、`uk_phone` | `idx_status` | — |
| 2 | `pet_member_pet` | `id` | — | `idx_member(member_id)` | `chk_pet_weight` |
| 3 | `pet_address` | `id` | — | `idx_member(member_id,is_default)` | — |
| 4 | `pet_category` | `id` | — | `idx_parent(parent_id,sort)` | — |
| 5 | `pet_item` | `id` | — | `idx_category_status`、`idx_species_stage`、`idx_sales`、`idx_merchant`、`idx_title` | — |
| 6 | `pet_item_sku` | `id` | `uk_sku_code` | `idx_item(item_id)` | `chk_sku_price`、`chk_sku_stock` |
| 7 | `pet_item_image` | `id` | — | `idx_item(item_id,sort)` | — |
| 8 | `pet_item_audit` | `id` | — | `idx_item(item_id,create_time)` | — |
| 9 | `pet_cart_item` | `id` | `uk_member_sku(member_id,sku_id)` | `idx_member` | `chk_cart_qty` |

| 13 | `pet_stock_log` | `id` | `uk_sku_order_type(sku_id,order_no,type)` | `idx_sku(sku_id,create_time)`、`idx_order_no` | — |

共 14 张表、45 个索引（含主键）、9 个业务唯一键、5 个 CHECK 约束，与设计 §6.2.1/§6.4 一致。

### 4.3 关键字段设计

| 设计点 | 字段/实现 | 说明 |
|---|---|---|
| 防超卖 | `pet_item_sku.stock INT` + `chk_sku_stock` | 扣减使用 `UPDATE ... SET stock=stock-? WHERE id=? AND stock>=?`，影响 0 行即库存不足 |
| 下单幂等 | `pet_order.client_token` 唯一键（可空） | MySQL 唯一索引允许多个 NULL，未传时不冲突 |
| 支付幂等 | `pet_payment.idempotency_key` 唯一键 + `uk_payment_no` | 重复回调命中唯一键即判定重放 |
| 重复扣减/回滚防护 | `pet_stock_log.uk_sku_order_type(sku_id,order_no,type)` | 同一订单同一 SKU 的 DEDUCT/ROLLBACK 各仅一条 |
| 初始库存与对账 | `pet_stock_log` 的 `ADJUST` + `order_no=''` | 空串而非 NULL，避免唯一键对 NULL 失效；满足 `Σchange_qty = 当前库存` |
| 超时关单 | `pet_order.status=0` + `idx_status_create(status,create_time)` + `expire_at` | 显式落支付截止时间，供倒计时与关单条件使用 |
| 收货快照 | `receiver_snapshot VARCHAR(1000)` 紧凑 JSON | 改地址不影响历史订单 |
| 宠物标记 | `pet_order.pet_snapshot`、`pet_order_item.pet_snapshot` | 支持"为哪只宠物买"的展示与筛选 |
| 金额自洽 | `total_amount` / `freight` / `discount_amount` / `pay_amount` | 应付 = 总额 + 运费 − 优惠（二期优惠字段预留） |
| 状态机 | `pet_order.status TINYINT`，0–8 | 与需求 §4.3.1 九状态一致，注释固化语义 |

### 4.4 索引与查询路径（对应设计 §6.5）

| 查询场景 | 条件 | 命中索引 |
|---|---|---|
| 订单超时扫描 | `status=0 AND create_time<? LIMIT 100` | `idx_status_create` |
| 会员订单六页签 | `member_id=? AND status=? ORDER BY create_time DESC` | `idx_member_status` |
| 商家订单隔离 | `merchant_id=? AND status=?` | `idx_merchant` |
| 商品列表/筛选 | `category_id=? AND status=1 AND audit_status=2` | `idx_category_status` |
| 宠物适配筛选 | `pet_species=? AND age_stage=?` | `idx_species_stage` |
| 商品详情 SKU | `item_id=?` | `idx_item` |
| 加购去重 | `member_id=? AND sku_id=?` | `uk_member_sku` |
| 支付幂等 | `idempotency_key=?` | `uk_idempotency_key` |
| 订单号查询 | `order_no=?` | `uk_order_no` |
| 库存流水对账 | `sku_id=?` | `idx_sku` |
| 消息未读角标 | `member_id=? AND read_flag=0` | `idx_member_read` |

```text
SKU 3 :  61 - 1 =  60
SKU 14:  82 - 2 =  80
其余 21 个 SKU：ADJUST = 当前库存
```

## 8 设计偏差、修正与待办

### 8.1 已处理的偏差

| # | 项 | 文档定义 | 实际实现 | 原因与影响 |

| 3 | 订单状态数量 | 需求/设计 §4.3.1 为 9 状态（0–8）；早期规划稿为 6 状态 | 采用 0–8 | 以正式需求/设计文档为准 |
| 4 | `sys_config` 无唯一键 | 若依表结构仅主键 | seed 采用 `DELETE ... LIKE 'mall.%'` + 显式 `config_id` 100–107 保证幂等 | 若依 `sys_config` 未建 `config_key` 唯一索引，不能依赖 `ON DUPLICATE KEY UPDATE` |

## 附录 B 关键演示 SQL

```sql
-- 1. 超时关单候选（status=0 且创建时间超过支付时限）
SELECT order_no, member_id, create_time, expire_at
FROM pet_order
WHERE status = 0 AND create_time < NOW() - INTERVAL 15 MINUTE;

-- 2. 条件扣减（防超卖核心）
UPDATE pet_item_sku SET stock = stock - 1 WHERE id = 5 AND stock >= 1;
SELECT ROW_COUNT();   -- 0 表示库存不足，应返回 PET-3001

-- 3. 支付幂等重放检测
SELECT id, order_no, idempotency_key, status FROM pet_payment
WHERE idempotency_key = 'seed-order-0002-pay-0001';

-- 4. 库存对账（返回 0 行表示一致）
SELECT s.id, s.stock, COALESCE(SUM(l.change_qty), 0) AS flow_sum
FROM pet_item_sku s LEFT JOIN pet_stock_log l ON l.sku_id = s.id
GROUP BY s.id, s.stock HAVING flow_sum <> s.stock;

-- 5. 订单六页签（示例：待付款）
SELECT order_no, total_amount, pay_amount, create_time
FROM pet_order WHERE member_id = 1001 AND status = 0 ORDER BY create_time DESC;
```
