# 00 · 给 AI 的配置说明（后端交接包）

> **你是接手本项目的 AI 助手。** 请完整阅读本文件后，按顺序在当前 Windows 机器上完成：
> ① 检查环境 → ② 初始化/恢复 `shop` 数据库 → ③ 配置后端连接 → ④ 构建并启动后端 → ⑤ 验收。
>
> 本包已经包含：后端源码、管理前端源码、数据库脚本、完整需求/设计文档、交接说明、校验脚本。
> **假设当前机器已安装**：Windows、JDK 17（或已有 JDK 多版本）、Maven、MySQL 8.0、Redis 7、Node.js/npm、Git。
> 若其中某项未安装，先停下并告知人类，不要自行下载安装包。

## 1. 执行协议（必须遵守）

1. **先读三份文档**：
   - 本文件；
   - `docs/02-设计文档/后端开发交接说明_v1.0.md`（工程约定、任务拆分、常见坑）；

3. **只向人类询问以下信息**：
   - MySQL `root` 密码（不要尝试暴力猜密码，失败 3 次即停）；

5. **不要修改** `docs/`、`db/`、`scripts/` 下的文件（配置后端时只改 `backend/` 下的 `application*.yml`）。
6. **不要把密码、Token 写入任何提交到 Git 的文件**。
7. 最终按 §12 输出一份交接报告。

## 4. 数据库：先判断再动手

### 4.1 判断 `shop` 库当前状态

```powershell
cd $ROOT
& $MYSQL -uroot --default-character-set=utf8mb4 -N -B -e @"
SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='shop';
SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='shop' AND LEFT(table_name,4)='pet_';
"@
```

根据结果选择场景：

| 结果 | 场景 | 动作 |
|---|---|---|
| `0` / 库不存在 | A：全新机器 | 执行 **01 → 02 → 03** |
| 约 `31`，且 `pet_* = 0` | B：已有若依基座 | **只执行 02 → 03**（绝不执行 01） |
| `45`，且 `pet_* = 14` | C：已初始化 | 跳到 §5，只跑校验 |
| 其他 | D：库被占用/结构未知 | **停下**，让人类确认是否备份后重建；禁止直接 drop |

### 4.2 场景 A：全新库（01 → 02 → 03）

```powershell
cd $ROOT
& $MYSQL -uroot --default-character-set=utf8mb4 -e "source ./db/01_base.sql"
& $MYSQL -uroot --default-character-set=utf8mb4 -e "source ./db/02_pet_mall.sql"
& $MYSQL -uroot --default-character-set=utf8mb4 -e "source ./db/03_seed.sql"
```

> `01_base.sql` 会创建 `shop` 库并导入若依 31 张系统表；**只在库不存在或为空时执行**。

### 4.3 场景 B：已有若依基座（02 → 03）

```powershell
cd $ROOT
& $MYSQL -uroot --default-character-set=utf8mb4 -e "source ./db/02_pet_mall.sql"
& $MYSQL -uroot --default-character-set=utf8mb4 -e "source ./db/03_seed.sql"
```

### 4.4 数据库验收

```powershell
cd $ROOT
# 期望：45 / 14
& $MYSQL -uroot -N -B -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='shop';"
& $MYSQL -uroot -N -B -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='shop' AND LEFT(table_name,4)='pet_';"

# 自动校验：期望 A/B/C 共 35 项 PASS、0 FAIL
& $MYSQL -uroot --default-character-set=utf8mb4 -t -e "source ./db/verify.sql"
```

预期关键数据：会员 2、宠物档案 3、分类 8、商品 12、SKU 24、订单 2、支付 1、库存流水 27。

### 4.5 数据库协作模式（两个人开发时）

**不要求两个人共用同一个 MySQL。** 推荐：

| 场景 | 做法 |
|---|---|
| 两人两台电脑（推荐） | 各自本地 MySQL；各自执行 `01 → 02 → 03` 得到一致的 `shop`；数据库不共享、Redis 也各自本地 |
| 两人同机 | 保留一份 `shop` 用于联调/演示；后端同学另建 `shop_dev` 副本并把 `application-druid.yml` 指向 `shop_dev`，避免互相执行 seed 清数据 |
| 需要联调时 | 约定一个"集成库"（例如其中一人的 `shop`），只在里程碑联调使用；演示前用 `03_seed.sql` 重置 |

**必须共享的是**：同一套 `db/*.sql` + 同一套表结构版本；任何 `ALTER`/新增字段都要提交迁移 SQL 到 Git，不能只改自己机器上的库。日常不要手改 schema。

### 4.6 开发前备份（建议）

```powershell
& '<MYSQLDUMP_EXE>' -uroot --default-character-set=utf8mb4 shop > "$ROOT\backup_shop_baseline.sql"
```

## 5. 配置后端连接（只改 `backend/ruoyi-admin/src/main/resources/`）

### 5.1 `application-druid.yml`

```yaml
spring:
  datasource:
    druid:
      master:
        url: jdbc:mysql://localhost:3306/shop?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=false&serverTimezone=GMT%2B8
        username: root
        password: '<MySQL_ROOT_PASSWORD>'
```

要点：
- 确认库名是 `shop`；
- 本地无证书建议 `useSSL=false`（若保留 `true` 出现握手告警，再改 false）；
- 密码按本机实际填写；正式交付前改为 `${DB_PASSWORD:...}` 占位符。

### 5.2 `application.yml`（三处）

1. **文件上传目录**（默认 `D:/ruoyi/uploadPath` 可能不存在）：

```yaml
ruoyi:
  profile: 'C:/Users/<用户名>/Desktop/萌宠优选_后端交接包/uploads'
```

并在本地创建该目录（PowerShell：`New-Item -ItemType Directory -Force $ROOT\uploads`）。

2. **Springdoc 扫描范围**（否则商城接口不出现在 Swagger）：

```yaml
springdoc:
  group-configs:
    - group: 'default'
      display-name: '测试模块'
      paths-to-match: '/**'
      packages-to-scan:
        - com.ruoyi.web.controller.tool
        - com.ruoyi.web.controller.mall
```

3. **可选（仅开发/演示）**：关闭验证码，方便接口联调；改完需重启后端。

```powershell
& $MYSQL -uroot -e "UPDATE shop.sys_config SET config_value='false' WHERE config_key='sys.account.captchaEnabled';"
```

> 演示环境如需验证码，可改回 `true`。生产禁闭验证码请遵循安全规范。

### 5.3 端口确认

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen -ErrorAction SilentlyContinue
```

被占用时改 `application.yml` 的 `server.port`，或先停掉占用进程。

## 9. 已知坑（务必对照）

| 现象 | 原因/处理 |
|---|---|
| `java -version` 显示 25 | 默认 JDK 不是 17；显式设置 `JAVA_HOME` 或在 IDEA 中选 17 |
| `mvn` 找不到 | 未安装 Maven；安装 3.9.x 并配置 `MAVEN_HOME`/`Path` |
| 启动报 Redis 连接失败 | Redis 未启动；先启动并 `redis-cli ping` |
| 启动报 `Unknown database 'shop'` | 还没执行 `01_base.sql`（场景 A） |
| 登录报验证码错误 | `sys.account.captchaEnabled` 为 true；按 §5.2-3 关闭并重启 |
| 上传图片失败 | `ruoyi.profile` 目录不存在或无写权限 |
| Swagger 看不到商城接口 | 未把 `com.ruoyi.web.controller.mall` 加入 `packages-to-scan` |
| MySQL 连接告警 SSL | 本地改 `useSSL=false` |
| 中文乱码 | SQL 执行带 `--default-character-set=utf8mb4`；源码/日志统一 UTF-8 |
| 订单页面提示库存不足 | 种子库存有 1 件和 0 件的 SKU，属正常演示数据 |
| 想重置演示数据 | 执行 `db/03_seed.sql`（会重置业务数据与订单时间，不要在他人演示时执行） |
| 想回滚业务表 | 执行 `db/rollback.sql`（只删 14 张 `pet_*`，保留若依表） |

## 10. 故障排查顺序

1. `setup/env-report.txt` 是否全部满足；
2. MySQL 是否能连、`shop` 表数量是否正确；
3. Redis 是否 `PONG`；
4. `application-druid.yml` 的 URL/用户名/密码是否本机正确；
5. 8080 是否被占用；
6. 构建日志第一条 `ERROR`（Maven 依赖、JDK 版本）；
7. 启动日志第一条 `Caused by`（数据库/Redis/端口）；
8. 把完整错误信息与已执行命令交给人类，不要反复盲目重试。

---

## 11. 禁止操作

- ❌ 对已有数据的 `shop` 执行 `db/01_base.sql`（会重建 31 张若依表）；
- ❌ 用 `DROP DATABASE shop` 解决问题；
- ❌ 使用 JDK 25 运行/编译本项目；
- ❌ 把 MySQL 密码、Token 写入 `docs/`、`db/`、Git 提交；
- ❌ 修改 `db/*.sql` 的库名/表结构来"绕过"问题；
- ❌ 在没有备份的情况下执行 `rollback.sql` / `03_seed.sql`（演示库除外）；
- ❌ 生产环境关闭验证码或使用默认 `token.secret`。
