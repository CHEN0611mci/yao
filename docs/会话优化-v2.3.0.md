# v2.3.0 会员会话优化

日期：2026-10-27；适用于本项目当前单机 Redis 部署。用户界面仍为 v1.2.0。

## 修改

- 设备列表、单设备撤销、退出其他设备、修改密码/手机号及封禁后的会话失效，原先使用 `KEYS member_tokens:*` 后逐条读取全站令牌。现在使用 `member_sessions:<memberId>` 的会员会话索引，仅访问该会员的数据。
- 列表按最多 256 个会话一批流水线读取令牌和精确剩余寿命，减少往返；过期索引按需清理。索引寿命覆盖对应令牌，并会自动过期。
- 创建、续期、删除令牌与索引使用 Redis Lua 原子操作。续期会检查令牌仍存在，避免已撤销会话被并发续期重新创建。
- 保持原令牌格式、前端接口及管理员/会员权限隔离；设备列表仍不返回令牌。
- 服务启动时使用增量 SCAN（COUNT 256）及批量读取重建现存令牌索引；在会话服务可用前完成。保留旧令牌值、有效寿命与历史会话的稳定 ID，不强制退出已有用户，不新增或重置数据库表。

## 验证

真实集成脚本：`user-ui/scripts/session-index-integration.mjs`。仅创建虚拟账号/令牌，测试结束清理本轮 Redis 压力数据。

- 新会话自动建索引；实际重启后，无 sessionId 的旧会话仍能登录并显示稳定 ID，迁移未延长其 TTL。
- 维护三个自己的会话，比较未加压力数据与增加 5000 个其他会员会话时的请求。每次设备列表都是四个 GET（三个会话加一次鉴权）；请求期间 KEYS 和 SCAN 调用增量均为零。
- 本机第一轮采样：10 次普通查询 P95 8.91 ms；增加 5000 个其他会员会话后 20 次查询 P95 9.33 ms。二者均为优化后的程序，验证的是开销不会随其他会员会话数增长；不是改造前后的提速比例，也不是生产容量承诺。最新原始采样见回执。
- 覆盖过期索引清理、会话滑动续期、撤销与并发续期竞争、跨会员拒绝撤销、退出其他设备、修改密码使自己的全部会话失效、其他会员保持有效及退出登录。
- 原会员功能 111 项、后台流程 62 项及运行库一致性 10 项复测通过。后端 Maven 构建通过，项目未配置 Java 单元测试。

原始回执：`verify/session-index/receipt.json`、`verify/member-features/`。

## 范围

正常会话操作的开销与当前会员的会话数有关；启动迁移仍需增量遍历现有 Redis 键。不是把扫描挪到每次请求，也没有清空用户会话。当前 Lua 使用单机 Redis 的多键原子性；迁移至 Redis Cluster 时需要重新规划键槽。

本轮只优化会员会话，若依系统管理其他缓存工具未整体改写。此前文档的会员会话 KEYS 限制由本版本取代。真实支付、短信找回、售后退款等未实现功能仍保持原范围。
