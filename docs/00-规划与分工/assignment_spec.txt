AI辅助软件开发
实  验  报  告 （四）
实验目的
本实验参考教材第九章“社区超市商城系统”的开发思路，以小组自主选题的商城系统为载体，完整经历企业级应用从需求分析、技术选型、架构设计、编码实现、测试验证到部署运维的全过程。掌握企业级互联网应用的设计方法、工程规范和交付能力，并能够使用 AI 编程工具辅助开发，同时保证过程可记录、结果可复现、系统可演示。具体实验目的如下：
掌握企业级需求分析与业务建模方法：能够明确商城目标用户、用户画像、角色权限和核心业务闭环，完成用例图、业务流程图、领域模型、ER 图、API 清单和非功能需求分析，形成可指导开发的需求文档。
掌握企业级技术选型与开发环境搭建：能够根据业务规模、团队能力和部署条件，合理选择编程语言、开发框架、数据库、缓存、消息队列、网关、容器、监控和 CI/CD 工具，并说明选型理由、替代方案和风险，而不是盲目堆技术。
学习前后端分离、分层架构、模块化设计与统一 API 规范：前端采用独立工程，只通过 JSON 接口与后端交互；后端按业务域划分模块，模块内遵循 Controller → Service → Mapper/Repository 分层；系统统一使用 Result 返回、统一异常处理、统一分页、统一鉴权、统一日志 traceId 和 OpenAPI 文档，避免 JSP/Servlet 式大泥球开发。
掌握商城核心业务闭环与数据一致性处理：能够实现商品浏览与搜索、购物车、下单、支付沙箱、库存扣减、订单履约、售后、评价、结算等核心流程，并处理库存防超卖、接口幂等、事务控制、分布式事务策略等企业级数据一致性问题。
学习企业级安全、性能与可靠性设计。
掌握 AI 编程全流程与关键决策记录方法：能够完整记录 AI 辅助编程过程，包括工具/模型版本、Prompt、生成内容、采纳或拒绝理由、人工修改、测试验证结果；能够记录架构、数据库、缓存、消息队列、认证、事务和部署等关键决策，保证实验过程可追溯、可复现。
掌握工程化交付与部署运维能力：能够使用 Git 分支规范、代码规范、单元测试、集成测试、E2E 测试、OpenAPI 文档、Docker/Docker Compose、Nginx、CI/CD 和环境分离完成项目交付；能够提供数据库脚本、初始化数据、启动命令、测试账号、部署脚本和回滚方案，实现一键启动或可复现部署。
培养团队协作、文档撰写与项目表达能：能够通过小组分工完成需求、设计、开发、测试、部署和实验报告，撰写规范的需求文档、设计文档、测试报告，并通过不超过 15 分钟的视频清晰讲解业务闭环、企业级能力、架构设计、关键难点和复现过程。
实验步骤展示
【要求】参考教材第九章“社区超市商城系统”的开发思路，各小组可自主选择商城业务领域，如校园二手、生鲜、医药、图书、宠物、跨境电商、社区团购等。但本项目不能停留在课堂 CRUD 演示层面，必须按企业级互联网应用标准完成，体现真实业务闭环、工程化开发、AI 辅助编程和可复现交付。
1. 项目立项与需求分析
给商城系统取名，明确目标用户、用户画像、核心痛点和使用场景。
明确角色与权限，如游客、会员、商家、运营、仓库、客服、财务、管理员等，并给出权限矩阵。
完成核心业务闭环：浏览/搜索、购物车、下单、支付沙箱、库存扣减、订单履约、售后、评价、结算等。
输出需求分析文档，至少包括：用例图、业务流程图、领域模型、ER 图、API 清单、非功能需求。
非功能需求必须可验证，如响应时间、并发量、可用性、安全性、可扩展性、可维护性。
2. 开发环境、技术选型与选型理由
参考教材第九章 9.1、9.2，完成开发环境准备与技术选型，并说明为什么选、替代方案是什么、风险是什么。
必须截图并说明所有用到的企业级技术栈、开发环境，包括：编程语言、开发平台、数据库、缓存、消息队列、注册配置中心、网关、容器、监控、CI/CD、测试工具等。
建议技术栈示例：后端 Spring Boot/Spring Cloud 或 .NET/Go；前端 Vue/React；数据库 MySQL/PostgreSQL；缓存 Redis；消息队列 RabbitMQ/Kafka；注册配置 Nacos/Consul；网关 Spring Cloud Gateway/Nginx；容器 Docker/K8s；监控 Prometheus/Grafana/ELK；接口文档 Swagger/OpenAPI；CI/CD Jenkins/GitHub Actions。
3. AI 编程全流程与关键决策记录
完整记录 AI 编程全流程：需求分析、架构设计、数据库设计、编码、测试、部署、优化。
每次使用 AI 必须记录：工具/模型/版本、Prompt、生成内容、是否采纳、拒绝理由、人工修改、测试验证结果。
关键决策必须留痕：为什么选该架构、数据库、缓存、消息队列、认证方案、事务方案、部署方案。
保证实验可复现：提供依赖版本、环境变量、数据库脚本、初始化数据、启动命令、测试账号、Docker Compose/K8s YAML、演示步骤。
不能只写“用 AI 生成”，必须附 AI 对话记录、日志、表格或截图。
4. 企业级应用必须考虑的问题
功能可用只是及格线，以下企业级能力必须至少覆盖多项，并有截图、代码、文档或测试报告证明：
安全：OAuth2/JWT、RBAC、密码哈希、HTTPS、防越权、防 SQL 注入、XSS/CSRF、接口限流、敏感数据脱敏、审计日志。
数据一致性：事务、索引、连接池、分页、库存防超卖、幂等、分布式事务策略，如本地消息表、Saga、TCC。
性能：Redis 缓存、异步处理、消息队列、CDN、连接池、压测报告，给出 QPS、RT、错误率。
可靠性：日志、监控、告警、健康检查、熔断、降级、重试、备份恢复。
工程化：Git 分支规范、代码规范、静态检查、单元测试、集成测试、E2E 测试、覆盖率、OpenAPI、CI/CD、Docker 化、配置分离。
运维部署：dev/test/prod 环境区分、部署架构图、回滚方案、容器化部署或云部署。
5. 交付物与视频讲解
每组提交：
源码、数据库脚本、部署脚本（一个压缩包）
企业级需求文档、设计文档、测试报告（三个文档）
PPT一份
录制一个不超过 15 分钟的视频，必须包含：业务闭环演示、角色权限演示、企业级能力演示、架构讲解、关键难点、AI 使用与复现、测试与部署、总结。
视频不能只放 PPT，必须录屏展示系统运行、权限拦截、异常流程、监控或压测结果。
6. 评分导向与高分关键
只有增删改查、无权限、无测试、无部署、无监控、无 AI 记录：低分。
功能完整且能运行：达到基本要求。
具备企业级架构、安全、性能、测试、部署、监控、AI 可复现记录：高分。
鼓励创新：推荐搜索、秒杀、优惠券、分布式事务、灰度发布、链路追踪、多租户等。
一句话总结：本项目要做的不是“能跑通的商城”，而是“可交付、可运维、可扩展、可审计、可复现的企业级商城系统”。
