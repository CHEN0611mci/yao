## 1. 项目定位

### 1.1 名称与一句话立意

- 推荐名：**「萌宠优选 · 宠物商城系统」**（备选：毛孩子优选 / 萌宠集市）
- 一句话：**面向养宠家庭的宠物用品零售商城，用「宠物档案 + 适用性筛选」解决"买错粮、买错尺码、买错年龄段"的核心痛点，并具备企业级交易闭环与可复现交付能力。**

### 1.2 目标用户与画像

| 画像 | 特征 | 核心诉求 | 对应功能 |
|---|---|---|---|
| 新手养宠人（20–30 岁） | 刚接宠物回家，不懂选品 | 不知道买什么、怕买错 | 宠物档案建档 → 按种类/年龄/体重推荐与筛选 |
| 忙碌上班族 | 复购为主，时间少 | 快速找到常买粮、看库存、下单快 | 搜索 + 购物车 + 快捷下单 + 订单追踪 |
| 多宠家庭 | 猫狗同养或 2 只以上 | 一单买多种、按宠物分开买 | 多宠物档案、购物车按宠物分组（可简化为标签） |
| 平台运营/商家 | 负责上架与发货 | 商品审核、库存、订单履约 | 管理后台：审核、上下架、发货、审计日志 |

### 1.3 与教材「社区超市」的差异化（写进文档即得分）

1. **宠物档案驱动选购**：档案字段（种类/品种/生日/体重/绝育/过敏源）→ 商品详情页显示"适合你家毛孩子吗"，列表支持按宠物筛选。低成本、强演示效果。
2. **商品属性宠物化**：适用物种（猫/犬/小宠）、适用年龄（幼年/成体/老年）、适用体重段、规格（kg/袋）、保质期。
3. **交易链路企业级加固**：原子扣减防超卖、支付回调幂等、超时未支付自动关单 + 库存回滚（教材只做了"弹框改状态"，这是明确对比点）。

### 1.4 角色与权限（4 角色，够演示、够写矩阵）

| 角色 | 关键权限 | 演示价值 |
|---|---|---|
| 游客 | 浏览首页/分类/搜索/详情 | 基础 |
| 会员 | 注册登录、宠物档案、地址、购物车、下单、支付、取消/确认收货、查看自己的订单 | 主闭环 |
| 商家 | 发布/编辑自己的商品、上下架、查看并处理自己的订单（发货） | **越权拦截演示点**（改他人商品 403） |
| 管理员 | 商品审核、分类管理、会员管理、订单管理、审计日志、系统管理 | RBAC 演示点 |

> 简化决策：**不单独做"运营/客服/财务"后台**，用管理员 + 权限码造数据展示；商家端页面复用管理后台的表单/列表，仅按 `merchant_id` 过滤与鉴权。这样 2 人可承受。

## 4. 业务闭环与关键设计

### 4.1 主流程

```
游客浏览首页/分类/搜索 → 商品详情
  → 注册/登录（会员）
  → 建/选宠物档案、选收货地址
  → 加入购物车（校验库存/上架状态）
  → 勾选结算 → 提交订单（事务：校验→原子扣库存→写订单/明细→清购物车→写库存流水）
  → 模拟支付（成功/失败/超时）→ 支付回调（幂等）
  → 商家发货 → 会员确认收货 → 订单完成
异常线：取消订单 / 15 分钟未支付自动关单并回滚库存 / 支付失败可重试
```

### 4.2 订单状态机

| 状态码 | 名称 | 允许操作 | 进入条件 |
|---|---|---|---|
| 0 | 待付款 | 支付、取消 | 下单成功 |
| 1 | 待发货 | 商家发货、会员申请取消（可选） | 支付成功 |
| 2 | 待收货 | 确认收货 | 商家发货 |
| 3 | 已完成 | 评价（可选） | 确认收货 |
| 4 | 已取消 | — | 用户取消（未支付） |
| 5 | 已关闭 | — | 超时未支付自动关闭 |

所有流转必须校验"当前状态 → 目标状态"合法，否则抛 `PET-3002`。

### 4.3 支付沙箱设计（差异化重点）

- `POST /api/pay/mock`：入参 `orderNo`、`channel`（WECHAT/ALIPAY/BALANCE）、`result`（SUCCESS/FAIL/TIMEOUT）。
- `POST /api/pay/callback`：请求头 `Idempotency-Key`；落 `pet_payment` 表，`idempotency_key` **唯一索引**；重复回调命中唯一键 → 直接返回成功，订单状态不变。
- 超时关单：Quartz 每分钟扫描 `status=0 AND create_time < now-15min` → 置 `5 已关闭` + 回滚库存（`stock = stock + qty`）+ 写 `pet_stock_log(type=ROLLBACK)` + 支付单置 TIMEOUT。
- 演示时提供后台"手动触发超时扫描"按钮或把阈值调到 1 分钟（`test` profile），避免录屏等 15 分钟。

### 4.4 防超卖设计

```sql
UPDATE pet_item_sku
SET stock = stock - #{qty}
WHERE id = #{skuId} AND stock >= #{qty};
```

- 返回影响行数 0 → `PET-3001 库存不足`，整单事务回滚。
- 订单创建、扣减、明细、清购物车、库存流水在**同一 `@Transactional(rollbackFor=Exception.class)`** 内。
- 表加 `CHECK (stock >= 0)` 兜底；`sku_id + order_no` 建库存流水唯一约束防重复回滚。
- 提供 `StockConcurrentTest`：20 线程抢库存 1，断言成功 1 单、失败 19。

### 5.2 全库约定

- 金额一律 `DECIMAL(10,2)`，禁止 float/double；库存 `INT` + CHECK。
- 所有业务表含 `create_time`、`update_time`；主数据策略：商品/会员/分类用 `del_flag` 逻辑删除，订单不删除。
- 订单号规则：`PET + yyyyMMddHHmmss + 4 位随机`，唯一索引。
- 索引：`order(member_id,status)`、`order(create_time)`（超时扫描）、`sku(item_id)`、`cart(member_id)`、`item(category_id,status)`。
- 收货信息在订单表存**快照 JSON/冗余字段**，避免地址修改影响历史订单。
- 交付 SQL 拆三份：`db/01_base.sql`（若依 `ry_20260417.sql` + `quartz.sql`）、`db/02_pet_mall.sql`（14 张业务表）、`db/03_seed.sql`（初始化数据）。

### 9.2 关键用例（必须写进测试报告）

1. 库存 1，20 并发下单 → 成功 1、失败 19，库存 0，流水 1 条 DEDUCT。
2. 同一 `Idempotency-Key` 回调重放 3 次 → 支付记录 1 条、订单状态只变一次。
3. 下单后不支付，超过阈值（演示用 1 分钟）→ 订单关闭、库存回滚、流水 ROLLBACK。
4. 会员 Token 访问 `/api/admin/**` → 403，审计日志新增一条。
5. 商家 A 修改商家 B 商品 → 403。
6. 金额精度：0.1 元 × 3 件合计 0.30，无浮点误差。
7. 库存 0 商品加购/结算 → 前端禁用 + 后端 `PET-3001`。
8. 重复提交订单（同 `client_token`）→ 只生成 1 单（Should）。
