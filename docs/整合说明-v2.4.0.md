# 仓库整合说明 v2.4.0（下载即完整运行）

更新：2026-10-27　｜　适用：Windows 10/11 + PowerShell 5.1+

## 1. 这次整合解决什么问题

v2.3.0 及之前，仓库的**用户端**有完整入口（`start-mall.bat`），但**管理端**只是"半成品"：

| 缺口 | 现象 | 本版处理 |
|---|---|---|
| 没有任何脚本构建 `admin-ui` | 下载后 `admin-ui/dist` 不存在，`start-admin-runtime.bat` 只能起静态服务，打开是 503/空页 | 新增 `setup/build-ui.ps1`，统一安装依赖 + 生成环境文件 + 构建两端 |
| `.env.production` 需手工复制并改值 | 忘记执行时管理端接口前缀为空，登录页请求打到 `/login` → 404，且无提示 | 构建脚本自动从 `.env.example` 生成 `.env.production`（`/prod-api`）与 `.env.development`（`/dev-api`），已存在则保留自定义值 |
| 两端要分别启动，且顺序依赖后端 | 需先 `start-mall.bat` 再 `start-admin-runtime.bat`，容易只起一半 | 新增 `start-all.bat`（后端 + 用户端 + 管理端一次启动）与 `setup/start-admin.ps1`（管理端幂等启动，含健康检查） |

## 2. 新增文件

| 文件 | 作用 |
|---|---|
| `setup/build-ui.ps1` | `-Target Both/User/Admin`、`-Force`。缺 `node_modules` 自动 `npm ci`（有 lockfile）或 `npm install`；`dist` 缺失或源码更新才重建 |
| `setup/start-admin.ps1` | 管理端一键启动：后端健康检查 → 构建 → `serve-user-ui.mjs` admin 模式 → 校验首页与 `/prod-api` 反代 → 打开浏览器。参数 `-AdminPort`、`-BackendPort`、`-StartBackend`、`-SkipBuild`、`-NoBrowser` |
| `setup/start-all.ps1` | 编排 `start-mall.ps1`（MySQL/Redis/后端/用户端）+ `start-admin.ps1`（管理端）。参数 `-UserPort`、`-AdminPort`、`-AdminOnly`、`-SkipBuild`、`-NoBrowser` |
| `start-all.bat` | 双击入口，等价 `setup\start-all.ps1` |
| `scripts/README.md` | 说明 `scripts/`（装机期）与 `setup/`（运行期）的分工，避免误用历史脚本 |
| `docs/整合说明-v2.4.0.md` | 本文件 |

## 6. 已知边界

- **首次构建需要联网**：`npm ci` 访问 registry。国内网络可先 `npm config set registry https://registry.npmmirror.com`（`build-ui.ps1` 失败信息里也会提示）。
- **后端**：仓库不含 `dist/ruoyi-admin.jar`（`.gitignore` 排除 `*.jar`）。首次启动时 `setup/start-backend.ps1` 会用 Maven 从源码构建；没装 Maven 时需自备 jar 放入 `dist\`。
- **数据库/缓存**：仓库不携带 MySQL/Redis 服务本体。已装好的机器直接 `init-db.bat`；全新机器先跑 `scripts/MySQL初始化.bat` 与 `scripts/Redis安装.bat`。
- **端口**：默认后端 8080、用户端 81、管理端 80。80 端口若被系统服务占用，用 `start-all.bat -AdminPort 8081`。
- **仅 Windows**：`setup/*.ps1` 与 `*.bat` 为 PowerShell/cmd 脚本，Linux 需手工执行等价命令（`npm ci`、`npm run build`、`java -jar`、`node setup/serve-user-ui.mjs`）。
