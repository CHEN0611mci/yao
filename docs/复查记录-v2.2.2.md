# v2.2.2 复查记录

日期：2026-10-27。本机实际后端/API/MySQL/Redis 验收，用户界面保持 v1.2.0。

## 发现与修复

1. **分类移位绕过两级限制**：有子分类的根分类移动到另一个根分类下面，旧接口返回成功并生成三级结构。现在拒绝该移动；创建子分类、移动、删除按分类 ID 顺序锁定相关行，避免并发生成循环或孤立分类。商品发布/编辑同步锁定目标分类，防止删除检查与新增引用交叉执行。
2. **明细数组中的空项触发 500**：`items:[null]`、`skus:[null]` 已实际复现；图片数组同类路径也补齐元素非空校验。现在返回 PET-1001 和具体参数提示。
3. **取消订单的索引间隙锁**：上一轮场景再次运行时捕获偶发死锁。MySQL `SHOW ENGINE INNODB STATUS` 确认，取消持有 `pet_order.idx_member_status` 的间隙锁并等待 SKU；新下单持有 SKU 并等待插入该索引。取消和关单现在使用已查到的订单主键精确更新，保留归属与状态条件。
4. **提交消息导致连接池耗尽**：连续混合并发时，后端实际出现 `GetConnectionTimeoutException: active 20, maxActive 20`，前端代理请求超时。原监听器 AFTER_COMMIT + REQUIRES_NEW 持有外层连接又申请新连接。现在 BEFORE_COMMIT 使用业务事务的连接，消息与订单一起提交/回滚，不额外申请连接。
5. **会员令牌日志误报**：会员 32 位 UUID 会被若依管理员 JWT 解析器记录为 ERROR。现在识别其形态并交给会员拦截器处理；它仍不能认证管理员身份。
