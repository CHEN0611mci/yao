五、设计文档落地要点（抽查）
--------------------------------------------------------------------------------
- 双状态分列：商品「审核状态 auditStatus」与「上下架 status」两列两标签，未合并；
- 审核通过 ≠ 上架：审核成功文案提示"请到商品管理页手动上架"；auditStatus!==2 时上架按钮 disabled+tooltip；
- 驳回强制下架：审核抽屉/确认文案明确"驳回后强制下架"；
- admin 编辑不重审、merchant 编辑强制重审+下架（两套文案，未共用）；
- reviewer：审核页无新增/编辑/上下架按钮（v-hasPermi + 后端 403 双保险）；
- 商家隔离：merchant 接口不传 merchantId；流水查询强制 skuId/orderNo 至少一个条件；
- 日期参数：订单 startTime/endTime、审计 beginTime/endTime 均为顶层参数，未使用 addDateRange；
- 库存：两接口无分页 → 不渲染 pagination / 不做前端假分页，max-height 内部滚动 + 「共 N 条（全量，无分页）」；
- 金额：MallMoney/formatMoney 两位小数，空值 —；时间：后端字符串直接展示或 parseTime；
- receiverSnapshot：按 JSON 字符串 parse，失败降级原文；发货后 logistics 追加展示；
- 上传：MallImageUpload 兼容 Result.data 与 AjaxResult，表单提交相对路径；
- 请求层：统一错误提示 message + PET-xxxx + traceId 后 6 位；401 只弹一次；429 读 Retry-After。
